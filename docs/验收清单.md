# 练食日记 · 验收与交付边界

## 本地核心流程

1. 首次打开：看到示例计划，缓存中没有自动创建个人档案。
2. 点击建档：输入 28 岁、170 cm、65 kg，选择周一 / 三 / 五，确认信息使用与变更预览。生成未来七日计划。
3. 尝试选相邻日期、输入未成年年龄或身体限制：阻止通用自动生成，原计划保留。
4. 打开训练日：显示热身、主训练和放松；查看动作步骤与示意图。
5. 开始训练，记录一组，暂停，退出再进入：已记录组数保留，暂停期间计时不增长。
6. 输入实际次数、负重，跳过或替换未记录动作。提前结束后显示「部分完成」，未执行组不会算完成。
7. 查看休息日：显示恢复提示，不提供必须完成任务，不增加训练分母。
8. 打开餐次：按计划记录，修改份量后重新保存，汇总更新但不出现重复餐次。
9. 添加不确定营养的外食：显示未知项提示，不假装全部营养已知。
10. 删除实际餐次：记录消失，原计划仍在。未来日期可调整计划但不能提前打卡。
11. 设置植物饮食和大豆 / 麸质过敏：生成和替换中不出现不符合条件的内容。忌口排除所有蛋白质来源时，生成失败且旧计划保留。
12. 记录页切换月份、查看历史计划、补记饮食、添加 / 修改 / 删除体重，检查统计。
13. 调整档案：确认变更日期后更新，没有覆盖历史及已有执行记录的日期。
14. 将训练移到恢复日：检查间隔校验及饮食保持不变。
15. 删除全部执行记录：档案与计划保留。注销：清除本地状态，回到示例浏览。

## 云端联调（需要部署与真实微信账户）

1. 配置三个集合、拒绝客户端直接访问的规则、索引与云函数环境变量。
2. 账户 A 首次连接上传；账户 B 不应读到 A 的档案。伪造请求 openid 字段不能改变数据归属。
3. 同一账户设备 1 更新，设备 2 使用旧版本上传：返回冲突，双方数据在选择前不被覆盖。
4. 重复发送相同 operationId：版本不应重复增加。
5. 断网记录再恢复：离线输入保留并上传。模拟上传成功但响应丢失后重试，不能重复应用。
6. 账户注销时先模拟云端故障：本地档案保留并显示失败；恢复后注销删除云端文档和本地档案。
7. 管理员新建草稿、审核、发布、停用；普通账户直接调用管理接口必须失败。
8. 发布新内容，用户更新后重生成：未来计划采用新版本，过去计划不变。
9. 配置错误、集合不存在或无权限时显示失败，不当作空账户自动覆盖。
