# 练食日记 · 微信小程序

围绕每日健身和每日饮食计划的原生微信小程序工程。采用米白、深绿与浅绿的界面，包含 9 个页面、本地数据持久化、可选微信云开发后端及自动化测试。

## 快速运行

1. 使用微信开发者工具导入当前 **SportAndDiet 项目根目录**，工具会读取 `project.config.json`。
2. 仅体验本地流程时使用测试号 / 游客模式；如工具要求有效 AppID，请替换配置里的 `touristappid` 为你自己的小程序 AppID。
3. 保持 `miniprogram/config.js` 的 `cloudEnv` 为空，无须安装前端依赖、申请接口密钥或部署后端。
4. 编译后从「今日」浏览示例，再点击「建立档案」生成七天计划。

本地模式数据仅保存在当前设备缓存。清除缓存会丢失数据，可先在「我的」导出。

## 已实现功能

| 页面 / 模块 | 功能 |
| --- | --- |
| 今日 | 今日训练、三餐、计划食物与实际摄入汇总、未建档示例 |
| 计划 | 七日安排、训练与休息日、独立训练改期、恢复间隔检查 |
| 建档 | 成年适用校验、目标、经验、训练日期与时长、过敏原、忌口、植物饮食、计划变更确认 |
| 训练 | 动作示意图与说明、逐组实际次数 / 秒数、可选负重、休息倒计时、暂停恢复、替换与跳过、提前结束、不适反馈 |
| 餐次 | 份量编辑、同类替换、过敏原过滤、实际摄入、手动外食、删除记录、单餐计划修改 |
| 记录 | 月历、历史日期补记、周统计、体重记录与近七次趋势 |
| 我的 | 账户连接、同步状态、冲突选择、内容更新、个人数据导出、删除与注销 |
| 内容管理 | 管理员验证、JSON 编辑器、草稿→已审核→发布→停用、审计记录 |
| 云函数 | 微信上下文身份、账户数据隔离、事务版本检查、提交幂等、删除、内容发布 |

## 配置云端

1. 在微信开发者工具绑定自己的 AppID，创建并关联云开发环境。
2. 将环境 ID 填入 `miniprogram/config.js` 的 `cloudEnv`。
3. 创建三个数据库集合：`journals`、`content`、`content_audit`。
4. 三个集合均配置为**客户端不可读、不可写，仅云函数访问**。自定义规则参考 `cloudfunctions/database.rules.json`，此文件需要手动在控制台应用，不会自动生效。
5. 为 `content` 按需建立 `kind` 升序、`updatedAt` 降序的组合索引，供管理员列表查询。
6. 右键 `cloudfunctions/journal`，选择「上传并部署：云端安装依赖」。依赖固定为 `wx-server-sdk` 4.0.2，运行时选择支持该 SDK 和 `crypto.randomUUID` 的受支持 Node.js 版本。
7. 内容管理员在**云函数环境变量**配置 `ADMIN_OPENIDS`，多个管理员的 OpenID 用英文逗号分隔；禁止把这个名单放到小程序端。OpenID 从受信任的云函数微信调用上下文获取，不能让用户自行提交身份。
8. 小程序「我的 → 连接微信云端账户」。云端为空时上传当前本地数据；云端已有记录时需确认是否使用云端版本。

云端账户 ID 根据服务端取得的 AppID 与 OpenID 派生，客户端提交的用户 ID 不参与权限判断。管理员入口不提供读取用户健康明细的能力。

平台接入参考：[微信官方示例工程](https://github.com/wechat-miniprogram/miniprogram-demo/blob/master/project.config.json)、[腾讯云开发：小程序调用云函数](https://docs.cloudbase.net/recipes/add-cloud-function-wechat-miniprogram)、[数据库事务](https://docs.cloudbase.net/database/transaction)、[微信云开发 SDK](https://github.com/wechat-miniprogram/wx-server-sdk)。

## 内容维护

默认动作与营养数据在 `miniprogram/lib/catalog.js`，仅用于开发演示，**未经专业审核，不能直接作为正式健身或膳食处方上线**。示意图由项目内的简单 SVG 绘制，只辅助识别动作，不替代完整教学。

管理员可从「我的 → 内容管理 → 从当前库新建」创建版本，在 JSON 中维护动作说明、分组、食物、营养估算与来源。已审核版本不可直接编辑；需另建版本。发布后普通用户通过「更新已发布内容库」获取，新生成计划使用新版本，历史快照保持不变。

目标字段已进入档案和计划依据，但当前模板以基础徒手训练为主；场地、器械偏好先保存，未提供完整健身房器械训练库。饮食显示的是食物营养估算，**没有基于个人身体信息计算每日能量处方**。专业模板、真实营养数据来源和更完整的训练分级应在正式发布前补齐。

## 数据与同步约定

- 全部日期按北京时间定义，训练跨午夜仍归属开始的计划日期。
- 训练完成率只计算计划训练日，部分完成单列；餐次记录率不表示营养达标率。
- 本地写入先落盘；连接云端后自动尝试上传，失败保留待同步状态；重新联网、再次打开小程序或点击立即同步时重试。
- 云端按账户存储单文档快照，事务检查版本，稳定的操作标识避免网络重试重复提交。
- 多设备冲突由用户选择云端或本地版本，当前不做逐条合并。页面再次进入时重新读缓存。
- 单账户同步内容目前限制为 750 KB；超过时提示导出整理，不会静默截断。长期运营应迁移到按记录分集合存储并实现分页。
- 重生成保留过去日期以及已有训练 / 饮食记录的整日计划；训练改期只改变训练，饮食日期不变。
- 训练按日期保存一个可暂停恢复的会话，结束后保留总结；首版不支持同一天多次独立会话。
- 注销先删除当前云端文档，成功后清除本地缓存；若云端删除失败或版本冲突，不显示成功。其他设备的旧版本上传会被拒绝，需重新连接或解决冲突。
- 管理员审计保存版本变更信息，不保存用户档案。上线前由运营者配置数据库备份与日志保留政策。

## 验证

安装 Node.js 18 或更新版本，在项目根目录执行：

```sh
npm test
npm run check
```

测试不需要安装依赖。覆盖日期边界、计划与过敏过滤、历史保留、训练计时、营养计算、统计口径、页面操作、离线恢复、同步冲突、账户隔离与内容权限。

静态检查验证 JavaScript / JSON 语法、页面文件、路由、事件处理函数、WXML 标签配对和资源引用；**不等同于微信官方编译器或真机测试**。云端测试使用数据库替身验证业务逻辑，不替代真实环境事务及权限联调。
